Technical SEO Audit Checklist: 24 Checks That Actually Matter

A prioritized technical SEO audit checklist covering crawlability, indexation, sitemaps, canonicals, redirects, Core Web Vitals and structured data — in the order to fix them.

How to use this checklist

Run these checks in order: crawlability first (if Google cannot reach a page, nothing else matters), then indexation, then on-page technical signals, then performance. Grade every finding by impact and effort so fixes ship in the right sequence.

Crawlability checks

Confirm search engines can reach everything that matters:

  • robots.txt allows important sections and blocks nothing critical by accident
  • XML sitemap exists, is current, and lists only canonical, indexable URLs
  • No important page is more than 3–4 clicks from the homepage
  • Orphan pages (no internal links) are found and linked or removed
  • Crawl budget is not wasted on faceted, parameter or infinite-space URLs
  • Server returns correct status codes — no soft 404s

Indexation checks

Verify the right pages are indexed — and only those:

  • Site: and Search Console coverage match your intended indexable set
  • Canonical tags point to the preferred version on every duplicate set
  • noindex is used deliberately, never left over from staging
  • Redirect chains are flattened; loops eliminated
  • Hreflang (if used) is reciprocal and returns valid targets
  • Duplicate title/meta patterns are resolved at template level

Performance and page experience

Core Web Vitals are a ranking input and a conversion input:

  • LCP under 2.5s on key templates (mobile)
  • INP under 200ms — check heavy scripts and long tasks
  • CLS under 0.1 — reserve space for images, fonts and embeds
  • Images are compressed, correctly sized and lazy-loaded below the fold

Structured data and final checks

Validate structured data against eligibility rules — only mark up content that exists on the page and qualifies for the schema type. Finish with HTTPS consistency, mobile rendering checks, and a log-file spot check if available. On-page technical checks

Technical SEO is not only about servers and sitemaps. The on-page checks catch problems that a crawl alone can miss. Start with titles and meta descriptions: every important page needs a unique title that describes its topic, and a meta description that a real person would want to click. Duplicate titles across dozens of pages usually mean a template problem, and fixing the template fixes every page at once. Then check headings. Each page should have one H1 that matches its topic, and H2 headings that follow a sensible order. A page with no H1, or with five H1s, confuses both readers and crawlers about what the page is for.

How to run the audit in a day

A full audit sounds like a week of work, but a focused audit of a small or medium site fits into a day if you work in order. Begin in the morning with a crawl using a crawling tool, and export the list of errors: broken links, redirect chains, missing titles, duplicate content, and pages with no internal links. While the crawl runs, open Search Console and note the coverage errors, the pages excluded from the index, and any mobile usability problems. These two sources together give you most of the findings.

Common audit mistakes

The most common audit mistake is fixing easy problems first. It feels productive to correct dozens of minor warnings, but a site with a blocked section gains nothing from polished meta descriptions on pages Google cannot reach. Always work in order: crawlability, then indexation, then on-page signals, then performance. Another common mistake is treating every warning as equal. A crawling tool will flag many things that do not matter for your site, such as a long URL on an unimportant page. Learn to ignore warnings that do not affect real pages or real visitors.

After the audit: turning findings into tickets

An audit only helps when its findings become work. For each finding, write a ticket that names the affected pages, the evidence, and the exact fix. "Fix the sitemap" is not a ticket. "Remove the 14 redirected URLs listed in the attached export from the XML sitemap, then resubmit it in Search Console" is a ticket a developer can finish in one sitting. Group related fixes together so one template change can resolve many pages at once, and estimate the effort for each group so the work can be scheduled honestly.

After the fixes ship, verify them. Re-crawl the affected pages, check the Search Console coverage report a few days later, and confirm that the error count is falling. Keep a short log of what was fixed and when, so the next audit starts from a known state instead of from scratch. Over time this log becomes a history of the site's technical health, and it shows clearly whether the site is getting healthier or whether the same problems keep returning. A good audit is not a one-off report. It is the start of a routine that keeps the site crawlable, indexable and fast as it grows.
